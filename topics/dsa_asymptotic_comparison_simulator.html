Asymptotic Comparison

Compare how quickly functions grow. Learn why logarithmic growth is slower than linear growth, and why exponential growth becomes huge.

1. The growth-rate ladder

For large input sizes, a typical order from slower growth to faster growth is:

1 < log₂ n < n < n log₂ n < n² < 2ⁿ < n!

This compares growth rates, not exact execution time. Constants and implementation details can matter for small inputs.

3. Understand each growth rate

Constant — O(1)

Work stays roughly the same when input grows. Example: reading arr[0].

Logarithmic — O(log n)

Each step shrinks the remaining problem, often by half. Example: binary search in a sorted array.

Linear — O(n)

Work grows in proportion to the input. Example: checking each item once.

Linearithmic — O(n log n)

Often appears in efficient sorting algorithms such as merge sort.

Quadratic — O(n²)

Often appears when two full loops are nested. If n doubles, work grows about four times.

Exponential — O(2ⁿ)

Work may double whenever one more input item is added. Some brute-force subset problems have this growth.

Factorial — O(n!)

Can appear when trying every possible ordering, such as a brute-force search through all permutations.

Exam tip: For a polynomial such as 7n³ + 4n² + 20, the highest-power term dominates, so its growth is O(n³).
