1. The main idea

Big O describes how an algorithm's work grows when the input size n increases. It helps us compare algorithms without depending on a particular computer.

O(1) < O(log n) < O(n) < O(n log n) < O(n²)

This is a typical order of growth, from slower-growing to faster-growing. Exponential time such as O(2ⁿ) grows even faster.

3. Everyday examples

O(1) — Constant time

Accessing an array element by index takes roughly one operation, regardless of array size.

value = arr[3]

O(log n) — Logarithmic time

Binary search repeatedly halves a sorted search range. Doubling the input adds only about one extra halving step.

search the middle → keep one half → repeat

O(n) — Linear time

Checking every item once means about twice as much work when the list doubles.

for each item in arr: inspect(item)

O(n log n) — Linearithmic time

Common in efficient comparison sorts such as merge sort. The data is processed across about log₂ n levels.

merge sort → divide into halves → merge

O(n²) — Quadratic time

A common pattern is one loop inside another, with each loop visiting all n items. Doubling n gives about four times the work.

for i = 1 to n:
  for j = 1 to n: work()
Remember: Big O focuses on growth, not exact seconds. It often ignores constants and lower-order terms: 3n² + 5n + 7 is O(n²).
